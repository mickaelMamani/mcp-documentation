## Overview

The Federer API is the internal markets platform for volatility and folio data. It is a REST API over HTTPS, JSON only, with one unversioned base URL per environment and a single Keycloak issuer shared by every domain. All routes below the base URL follow the same rules for authentication, headers, paging, errors and data formats, so a client written for one domain works for the other without change.

| Domain | Scopes | What it covers |
|---|---|---|
| volatility | `volatility:read`, `volatility:write` | Surfaces, plugs, calibration and implied vol, for example `GetSurface`, `Plug`, `Recalibrate`. |
| folio | `folio:read`, `folio:write` | Folios, positions and folio lifecycle, for example `SearchFolio`, `GetFolioPositions`, `CreateFolio`. |

The machine readable catalogue of domains and endpoints is published as `manifest.json` next to this file.

## Environments and base URLs

| Environment | Base URL | Notes |
|---|---|---|
| prod | `https://api.example.internal` | Production data. Change controlled, rate limited, audited. |
| uat | `https://api.uat.example.internal` | Pre-production. Same schema as prod, data refreshed weekly from a masked extract. |
| dev | `https://api.dev.example.internal` | Synthetic data, reset every night. Use it for integration tests. |

The base URL carries no version segment. Environments differ only by host, never by route, payload or status code, so the same client code runs everywhere by swapping the base URL. Identifiers are not portable: a `surfaceId` obtained in uat does not exist in prod.

## Authentication

Authentication uses Keycloak OIDC with the client credentials grant on the `markets` realm. Request a token from `https://auth.example.internal/realms/markets/protocol/openid-connect/token` and send it on every call as `Authorization: Bearer <access_token>`. Tokens are short lived, so cache one per client and refresh it before expiry rather than requesting one per call.

```http
POST /realms/markets/protocol/openid-connect/token HTTP/1.1
Host: auth.example.internal
Content-Type: application/x-www-form-urlencoded
Content-Length: 114

grant_type=client_credentials&client_id=<client_id>&client_secret=<client_secret>&scope=volatility:read+folio:read
```

The `Content-Length` above frames the placeholder body; send the byte length of the form encoded body you actually post, or let the HTTP client compute it. The response carries `access_token`, `token_type` and `expires_in` in seconds.

| Scope | Grants |
|---|---|
| `volatility:read` | Read surfaces, plugs and quotes, and compute implied vol. |
| `volatility:write` | Apply or delete plugs and trigger a calibration. |
| `folio:read` | Read folios and positions. |
| `folio:write` | Create and close folios. |

A missing or expired token returns 401, a valid token without the required scope returns 403, and so does a resource owned by another desk.

## Common headers

| Header | Direction | Required | Description |
|---|---|---|---|
| `Authorization` | request | yes | `Bearer <access_token>` issued by the `markets` realm. |
| `Accept` | request | yes | Always `application/json`. |
| `Content-Type` | request | on write | `application/json` on any request that carries a body. |
| `X-Correlation-Id` | request | no | Caller supplied id tracing one operation across services. |
| `X-Business-Date` | request | no | ISO date for as-of queries, for example `2026-08-28`. Defaults to today. |
| `Idempotency-Key` | request | no | Non-idempotent POSTs, both creations such as `CreateFolio` and state changes such as `CloseFolio`. A replay with the same key returns the first result. |
| `X-Correlation-Id` | response | always | Echo of the request value, or one generated by the platform. |
| `Retry-After` | response | on 429 | Seconds to wait before retrying. |
| `Deprecation` | response | on deprecated routes | Route scheduled for removal. |
| `Sunset` | response | on deprecated routes | Date after which the route stops working. |

Unknown request headers are ignored.

## Pagination

Every collection response is paginated with the query parameters `page`, 1-based with default 1, and `pageSize`, default 50 and maximum 500. They apply to `GET` collections and to search endpoints that take a body, such as `SearchFolio`, where they remain query parameters. A `pageSize` above 500 is rejected with 400.

```json
{
  "items": [],
  "page": 1,
  "pageSize": 50,
  "totalCount": 1234
}
```

`totalCount` is the number of items matching the request, not the number returned in `items`. Iterate while `page * pageSize` is lower than `totalCount`. Ordering is stable for a given request, but rows inserted between two calls can shift results, so prefer one large page over many small ones when consistency matters.

## Errors

Errors use `application/problem+json` (RFC 7807) with the same shape everywhere. `type` is a stable slug URI to branch on, `detail` is human readable and may change, and `traceId` identifies the call in the platform logs.

```json
{
  "type": "https://api.example.internal/problems/surface-not-found",
  "title": "Surface not found",
  "status": 404,
  "detail": "No surface with id VOL-EURUSD-2026-08-28.",
  "instance": "/volatility/surfaces/VOL-EURUSD-2026-08-28",
  "traceId": "3f2a1c9e-77b4-4a5d-9c31-0b1e6d8a4f52"
}
```

| Status | Meaning | What to do |
|---|---|---|
| 400 | Malformed or out of range parameter. | Fix the request, do not retry as is. |
| 401 | Missing or expired token. | Get a new token and retry once. |
| 403 | Required scope missing, or the resource belongs to another desk. | Ask for the scope listed on the endpoint; for a folio owned by another desk, ask the owning desk or use a token entitled to it. |
| 404 | No such resource for that id or date. | Check the id and `X-Business-Date`. |
| 409 | Locked surface or closed folio. | Re-read the resource, do not blind retry. |
| 422 | Rejected by a business rule. | Read `detail` and change the payload. |
| 429 | Rate limit exceeded. | Back off, see the rate limits section. |
| 500 | Unexpected platform failure. | Retry once, then report `traceId`. |

## Rate limits

The platform allows 600 requests per minute per client, counted on the token client id over a sliding window and shared by all domains. Exceeding the quota returns 429 with a `Retry-After` header expressed in seconds and a problem document.

Retry policy for 429 and 500: wait the number of seconds given by `Retry-After` when it is present, otherwise start at one second, double the delay on each attempt, add random jitter of up to 50 percent of the delay, cap the delay at 60 seconds and give up after 5 attempts. Never retry a non-idempotent POST sent without an `Idempotency-Key`, because the first call may already have succeeded. Prefer larger pages and fewer calls over parallel fan-out.

## Versioning and deprecation

The platform release is `platformVersion`, currently 2.3.0, in `major.minor.patch` form. Each endpoint records its minor line in its own `version` field, for example 2.3. No breaking change ships inside a major: a minor release may add optional fields, optional parameters and new enum values, so a client must ignore unknown JSON fields instead of failing on them. A breaking change ships as a new major on a separate base URL.

| Signal | Where | Meaning |
|---|---|---|
| `platformVersion` | manifest and this file | Current platform release. |
| `version` | endpoint front matter | Minor line in which the endpoint is available. |
| `Deprecation` | response header | The route still works but a replacement exists. |
| `Sunset` | response header | Date after which the route returns 410. |

A deprecated endpoint is also flagged `deprecated: true` and names its replacement, as `ListFolios` does for `SearchFolio`. The sunset date is announced as early as possible and is carried on the `Sunset` response header, so read that header and plan the migration from the date it gives rather than from a fixed notice period.

## Conventions

| Topic | Rule |
|---|---|
| Instants | ISO 8601 in UTC with a trailing Z, for example `2026-08-28T10:00:00Z`. |
| Business dates | Plain ISO dates without a time zone, for example `2026-08-28`. |
| Tenors | ISO 8601 durations, for example `P1M`, `P3M`, `P1Y`. |
| Numbers | JSON numbers, dot decimal separator, no thousands separator. |
| Volatilities | Volatility points, so `18.75` means 18.75 percent. Plug shifts use the same unit. |
| Currencies | Uppercase ISO 4217 codes, for example `EUR`, `USD`. |
| Enums | Lowercase strings such as `published` or `option`. An unknown value is rejected with 400. |
| Identifiers | Prefixed and opaque: `VOL-EURUSD-2026-08-28`, `PLG-0004212`, `FOL-000123`, `POS-0009981`, `QT-00034512`. Do not parse them. |
| Trace ids | GUIDs, returned in every problem document. |
| Null versus absent | On read, an absent field was not requested and `null` means no value. On write, an absent field leaves the stored value unchanged and an explicit `null` clears it. |
